PHP 인증모듈 보안 취약점에 따른 API 방식 전환 요청 안내

안녕하세요. 코리아크레딧뷰로(KCB) 입니다.
KCB 본인확인서비스를 이용해 주셔서 감사합니다.

최근 PHP에서 인증 없이 원격으로 서버를 장악할 수 있는 치명적 보안 취약점(CVE-2026-109618, CVE-2026-109619)이 공개되어, 한국인터넷진흥원(KISA)과 해외 보안기관에서 보안 업데이트를 권고하고 있습니다. 이 취약점은 PHP 8.2.35·8.3.36·8.4.27·8.5.12 이상 버전에서 해결되었으나, PHP 8.1 이하 버전은 보안 지원이 종료되어 패치가 제공되지 않습니다.

취약한 서버가 공격을 받으면 연동 방식과 관계없이 귀사 서버에서 처리되는 이용자 개인정보(성명, 생년월일, 휴대폰번호 등)가 유출될 수 있습니다. 귀사가 사용 중인 KCB PHP 인증모듈은 PHP 8.1 이하에서만 동작하므로, 먼저 API 방식으로 전환하신 뒤 PHP를 보안 지원 버전으로 업그레이드해 주실 것을 요청드립니다.

  귀사 이용 현황 (KCB 확인 기준)
회원사코드 $_FIELD_01$
이용 서비스 $_FIELD_02$
사용 중인 모듈 PHP
  왜 API 방식인가요
  • KCB PHP 모듈은 PHP 8.1 이하에서만 동작하므로, API로 전환해야 PHP를 보안 지원 버전으로 업그레이드할 수 있습니다. API 전환 전에 PHP를 8.2 이상으로 업그레이드하면 본인확인서비스가 중단되니 반드시 API 전환을 먼저 진행해 주세요.
  • API는 서버에 모듈을 설치하지 않고 표준 HTTPS(TLS 1.2 이상)로 연동하므로, 개발언어·버전에 따른 모듈 호환 문제와 향후 모듈 교체 부담이 없습니다.
  • 다른 언어의 모듈로 바꾸는 방식은 언어 환경에서 또 취약점이 발견될 경우 동일한 교체가 다시 필요하여, KCB는 API 방식을 권장드립니다. API로 전환하셔도 계약 및 이용요금 변경은 없습니다.
  요청사항
NAT IP 회신 NAT IP를 [운영 공용 메일]로 회신: 메일 제목을 [PHP전환회신][$_FIELD_01$]로 해 주시면 빠르게 처리됩니다.
API 방식
전환 완료		 KCB가 전달하는 클라이언트 정보와 규격서 등 자료를 참고하여 전환 부탁드립니다.
PHP
보안 업데이트		 API 전환 후 PHP를 보안 지원 버전(8.2.35·8.3.36·8.4.27·8.5.12 이상)으로 업그레이드 부탁드립니다.
귀사 서버의 보안 업데이트는 귀사에서 적용해 주셔야 하는 점 참고부탁드립니다.
※ 미리 API 전환 안내를 받으신 회원사도 API 전환 후, PHP 업그레이드까지 진행해주시기 바랍니다.
임시 보호조치 전환 완료 전까지는 불필요한 인터넷 노출 최소화, 접근 제한 등 가능한 보호조치를 적용해 주시기 바랍니다.
  전환 절차
① NAT IP 회신
② KCB에서 IP 등록 후 클라이언트 정보(client_id, client_secret) 발급 — 회신 후 1~2영업일 내 전달 예정
③ API 개발 및 연동 확인
④ 운영계 전환
⑤ 기존 PHP 모듈 삭제
⑥ PHP 보안 지원 버전으로 업그레이드
